# Keeta 外賣人生 3D（Keeta Delivery Life 3D）

香港大埔外賣員模擬遊戲 —— 單檔 HTML，雙擊即開即玩（無需伺服器、無需安裝）。

- **引擎**：three.js 0.186.1（ES Module，unpkg CDN）
- **渲染**：Toon / Cel Shading ＋ 自訂描邊後處理，低多邊形 stylized 風格
- **地圖**：大埔怡雅苑（5 座）＋ 富善商場（4 餐廳）＋ 新興花園（5 座）三區合併開放世界
- **玩法**：接單 → 取餐 → 送達 → 收錢，管理信譽／水／能量／疲勞／租金／油量

---

## 點玩（操作）

| 鍵 | 動作 |
|---|---|
| `W A S D` | 移動 |
| `Shift` | 衝刺（雙倍消耗水／能量） |
| 滑鼠 | 轉視角 |
| `T` | 開／關手機（接單面板） |
| `E` | 互動（取餐、送達、買嘢、入店） |
| `R` | 上車／落車（單車／電單車） |
| `F` | 屋企瞓覺（可選 1–24 小時） |
| `1 / 2 / 3 / 4 / 5 / 6` | 車店／購物購買 |

## 遊戲邏輯（完整規格）

### 開局
現金 **$100** ＋ 一架**單車**（騎住開局）。要送單賺錢先買得起電單車（$3000）。

### 訂單流程
1. 按 `T` 開手機睇訂單（同時顯示 3–5 張，睇信譽）
2. 揀單 → 去餐廳取餐點（`E` 取餐）→ 外賣袋上身
3. 送去大樓正門（送達點有 NPC 等緊）→ `E` 送達 → 收錢

### 信譽系統（⭐）
- 起始 **30**；每單準時送達儲 streak，**連 5 單 ＋3**
- 任何單**遲到（取餐或送餐過時限）−3**，錢照收但唔計 streak
- 信譽影響接單：
  - `>60` → 手機顯示 **4 張**訂單（且好單機率 50% 起）
  - `>80` → 顯示 **5 張**訂單（好單機率 80%），並解鎖尾箱孖單
- 信譽越高，揀到貴單／好單機會越高（分段乘數）

### 孖單（尾箱）
- 信譽 ≥80 解鎖；車店買尾箱：
  - **Lv1 $500** → 同一時間接 **2 單**
  - **Lv2 $1000** → 同一時間接 **3 單**
- 多單要全部送晒先算完成

### 租金
每日 **$300**，喺 **00:00 日界**扣；唔夠錢會進入欠租狀態（`debtDays`），連續欠租有壓力。

### 生活系統（水／能量／疲勞）
| 移動方式 | 消耗（per km） |
|---|---|
| 步行 | 水 5 / 能量 10 |
| 單車 | 水 10 / 能量 8 |
| 電單車 | 汽油 1.5（油缸 100） |

- **衝刺（Shift）**：水＋能量消耗**雙倍**（電單車冇衝刺模式）
- **怠速**：每 2 遊戲分鐘 水−1／能量−1／疲勞+0.8
- **疲勞 >75 或 能量 <25**：速度 ×0.75（「好攰」警告）
- 回復：**759 便利店**買水 **$12**（+30 水）、買飯 **$50**（+40 能量）
- 瞓覺（屋企 `F`）只清疲勞，**唔會**回復水／能量（要食嘢先得）

### 升級車店（位置：停車場旁）
| 選項 | 價錢 | 效果 |
|---|---|---|
| 單車 | $800 | 移動速度 +40%（開局已有） |
| 電單車 | $3000 | 移動速度 +80%，用油 |
| 速度升級 | $500／級 | +10%／級，最多 3 級 |
| 入油 | $6–10／km 浮動 | 加滿電單車油缸 |
| 尾箱 Lv1 | $500 | 同時接 2 單（需信譽 ≥80） |
| 尾箱 Lv2 | $1000 | 同時接 3 單 |

### 時段與價格
- 價格帶 $18–40，按距離遞增；尖峰（午市／晚市）×1.3–1.45
- 加急單（urgent）×1.3 價、時限減半
- 每單都有 deadline（取餐＋送餐兩段），普通單 1km 內約 10 分鐘

### 地圖（OSM 數據源，中多邊形）
- **怡雅苑**：A 座怡禮／B 座怡順／C 座怡厚／D 座怡達／E 座怡亮（5 座新十字型）
- **富善商場**：759 阿信屋／稻香／麥當勞／大家樂（可入大堂）
- **新興花園**：康智／康仁／康信／康誠／康民閣（5 座，安埔路北面）
- 屋企（可瞓覺）、停車場、噴水池、遊樂場、籃球場、有蓋行人道、升級車店

## 設計意圖與被否決方案

呢節記錄「點解咁設計」同「試過／諗過但放棄咗咩」——比純規格更重要，防止下一手開發者（或 AI）好心做壞事推翻已驗證嘅決定。

### 設計意圖（揀咗嘅路，點解）
| 決定 | 設計意圖 |
|---|---|
| 單檔 HTML（three.js + unpkg CDN） | 分享零門檻（開 URL 即玩）、免安裝免伺服器、原型驗證最快 |
| 全部幾何程式化生成（無外部模型） | 源碼即資產（可 diff／可版本控制）、檔細（188KB）、貼圖都係 Canvas 生成，唯一外部依賴係 three.js CDN |
| Toon / Cel 渲染＋描邊（Claude 收口） | 中多邊形下最「靚」嘅性價比路線：低模+卡通風格=遮醜兼有風格，唔使高模高貼圖 |
| 數據源 OpenStreetMap（唔用 Google Maps） | OSM 免費開放、實地座標、可程式化合併第二區；Google Maps 版權／ToS 限制商用重製 |
| 信譽做核心壓力（唔淨係錢） | 錢可以無限刷，信譽先係「有得揀」嘅資源：影響單量（3–5 張）同單質（貴單機率），令玩家要顧及表現而唔係掛機 |
| 孖單鎖喺信譽 ≥80＋尾箱升級 | 經濟曲線平滑：技術玩家（高信譽）先有產能升級，低信譽階段只能一單一單捱 |
| 生活系統要「輕」 | 只做水／能量／疲勞／租金四個數字，唔做模擬市民式複雜需求——保持外賣 loop 為主軸 |

### 被否決方案（試過／諗過，記錄點解唔得）
| 方案 | 點解否決 |
|---|---|
| **Google Maps 做數據源** | 版權／ToS 限制＋非開放格式；用戶拍板 OSM |
| **高清寫實畫質（對標 gpt astra）** | 單檔 three.js＋程式化幾何做唔到 AAA 貼圖品質；改行「中多邊形 stylized」路線（用戶拍板） |
| **第一區做啟德 1–2 km²** | 最初規劃；原型落地改用大埔三區（怡雅苑＋富善＋新興花園）驗證核心 loop，啟德留作擴展地圖 |
| **重型生活系統（詳細生理／社交）** | 用戶拍板「生活系統要輕」——會搶走送單節奏 |
| **訂單數量無上限** | 初期提議過；收口做 3–5 張（信譽門檻）＋孖單尾箱（上限 3 單同時）——有限先有取捨 |
| **無租金（自由模式）** | 用戶要求「增加壓力」→ 加 $300/日租金（00:00 扣） |
| **睡眠回復水／能量** | 會令 759 買嘢冇意義；用戶拍板：睡眠只清疲勞，水／能量一定要買食物 |

## 開發故事：3 個 AI 一齊砌出嚟

呢隻遊戲唔係一個人寫嘅，係 **3 個 AI 透過本地聊天室協作**完成：

```
用戶（驗收員／拍板人）
   │ 實測回報 bug、拍板數值
   ▼
豆包（整合／驗收）── 主檔整合、地圖 merge、全測試、同用戶溝通
   │ ▲
   ▼ │
WorkBuddy（實作／驗收）── 3D 場景建模、細節層、驗證工具開發
   │ ▲
   ▼ │
Qwen（設計／規格）── 玩法／數值／經濟系統規格、覆核、spec 文件
```

### 協作流程
- 三個 AI 喺本機聊天室「3D 遊戲開發」即時討論，每條訊息有角色分工（Qwen 出規格、WorkBuddy 實作、豆包整合覆驗）
- 每小時有一個**定時監察任務**自動睇聊天室，將 Qwen／WorkBuddy／用戶嘅新回覆整合推進
- 5 輪架構推進：
  - **R1** 概念＋核心迴圈（接單→送達）收口
  - **R2** 玩法＋地圖＋規則（信譽／孖單／租金／生活系統）派工
  - **R3** 技術方案（three.js 單檔、碰撞、OSM 數據）
  - **R4** 資產＋分工（場景建模、貼圖、NPC）
  - **R5** Game Plan 收口交用戶拍板
- 用戶係「行動派驗收員」：逐個 bug 實測回報（NPC 冇手腳／單車陷入地下／送達點 NPC 企入建築…），全部由團隊修復；所有數值（$100 開局、$300 租金、信譽機制、孖單價錢…）都係用戶逐項拍板

### 品質紀律（WorkBuddy／Qwen 建立）
- 改源碼前必先 timestamp 備份入 `_backups/`
- 驗收必用數值證據（tri／draw call／fps／像素佔比），唔靠肉眼
- 驗收報 FAIL 先查驗證工具，確認工具無誤先改產品碼
- merge 驗證雙軌：常數同源檔逐項比對 ＋ 實際 mesh 世界 bbox vs 聲稱值

## Claude 最終收口：佢做咗啲咩（豆包分析）

Claude 收到團隊完整遊戲（源碼＋規格＋bug 修復記錄）後，喺一日內重寫收口。分析如下：

### ✅ Claude 做得好嘅
1. **視覺引擎重寫（最大改動）**：
   - `MeshStandardMaterial` → **`MeshToonMaterial`**（toon / cel 渲染），配合自訂 **描邊 post-processing shader**（`ShaderMaterial` + `WebGLRenderTarget`），令成個遊戲變 stylized 卡通風格
   - 自訂**天空 gradient**（Canvas 生成 equirectangular 貼圖）＋太陽 sprite、`NoToneMapping`——畫面立即有「風格」
2. **幾何效能重構**：
   - `mergeGeometries` 大量合併（牆／玻璃／陽台／欄杆逐個 bucket merge），draw call 大減
   - 樹葉用 `InstancedMesh`、環境 speck（雜訊點）增加細節密度
   - 車型生成器（巴士／van／私家車）、統一 toon 色板
3. **完整保留遊戲邏輯**（逐項對照我哋規格，全部一致）：
   - 開局 **$100＋單車**（最新拍板值）✅
   - 信譽／孖單／租金 $300／生活消耗／759 購物／車店 6 項 ✅
   - 車店「已有單車唔誤扣錢」防禦都抄咗 ✅
4. **保留合併地圖**：怡雅苑＋富善商場＋新興花園 5 座，送達點／收件亭／行人路
5. **保留測試文化**：`__WT_*` 測試接口全部保留（`__WT_GAME`／`__WT_SHG_CLAIM`／`__WT_MERGE_PROBE`…），連我哋嘅 bug 修復註釋（雙重偏移）都寫埋喺源碼

### ⚠️ Claude 同我哋版嘅差異（值得留意）
| 項目 | 豆包團隊版 | Claude 收口版 |
|---|---|---|
| 渲染 | Standard 材質＋冷 pastel 光照 | Toon ＋ 描邊後處理（更卡通） |
| 檔案大小 | ~360 KB | ~188 KB（重寫精簡） |
| SHG 位置 | 北移 26m（offset −165） | 再北移 21m（offset −186），送達點跟住移 |
| deadline 公式 | 1km 內 10 分鐘（待用戶拍板每 150m+1 分鐘） | 維持 1km 內 10 分鐘 |
| 角色 NPC | 簡約人形 | 保留人形（toon 風格） |

### 結論
Claude 版最大價值係**視覺風格升級**（toon＋描邊＝好接近用戶最初要求嘅 MagicCarpet 冷 pastel stylized 方向），同時**零走樣**保留全部已拍板遊戲邏輯——係一個好嘅收口。後續要 merge 返嘅話，以 Claude 版為視覺基底、豆包團隊版做邏輯回歸對照，雙軌驗證。
